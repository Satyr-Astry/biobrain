## 1. ★ 核心论文：拓扑 > 动力学（arXiv 2404.17128）

**作者**：Xiaoyu Zhang, Pengcheng Yang, Jiawei Feng, Qiang Luo, Wei Lin, Xin Lu
**投稿**：2024-04（v4 2024-08）· 期刊版：ScienceDirect S2667325825000792《Network structure governs Drosophila brain functionality》

### 四个关键结论（原话）

1. **"even with rudimentary neuronal activation mechanisms, models grounded in real neural network structures can generate activation patterns strikingly similar to those observed in the actual brain"**
   → 即使神经元机制简陋，**只要结构真实**，激活模式就与真实大脑高度相似

2. **"A significant discovery was the consistency of activation patterns across various neuronal dynamic models"**
   → **换不同的动力学模型，激活模式却一致**（同一网络结构下）

3. **"These results challenge the prevailing view that solely relies on neuron count or complex individual neuron dynamics"**
   → **挑战"靠神经元数量或复杂个体动力学"的主流观点**

4. **"a reconnect rate of at least 0.1% was sufficient to disrupt the previously observed activation patterns"**
   → **仅 0.1% 的重连就足以破坏激活模式**（结构极度敏感 = 拓扑是信息载体）

### 其他发现
- **网络距离而非空间距离**是激活模式的首要决定因素
- **视觉与嗅觉系统在网络层面近乎完全分离**
- **半球协同**：单侧输入刺激也会激活两侧的视觉相关神经元
- **半球间通信重要**

### ★ 对主人项目的直接启示

项目的 P0 病灶是"**不同输入得到同一个激活模式**"。小悠此前的诊断说：
> 根因是 `tick_activation` 的扩散**无方向 + 无符号 + 无选择性** → 收敛到同一吸引子

**这篇论文给出了更强的判断**：
> **问题不在于"动力学不够复杂"，而在于"结构不是真的"。**
> `Tract.dynamics` 是**随机初始化**的——它是**假结构**。
> 论文说 0.1% 重连就破坏模式 ⇒ 反过来说：**随机结构 = 随机激活模式 = 无法承载语义**。

**结论修正**：小悠之前的两轮结构编辑（带符号、单向流）方向对，但**还差最关键的一步——结构本身必须是"有信息的"，不能是随机初始化的**。

## 2. Eon Systems / Shiu et al. 的极简配方（Nature 634, 2024）

### 模型构成（只有 4 样东西）

```
① 连接图          ← FlyWire whole-brain connectome
② 权重            ← 突触数量（synapse count）
③ 兴奋/抑制映射    ← 神经递质预测
④ 神经元模型       ← LIF（leaky integrate-and-fire）
```

**规模**：125,000+ 神经元 / 50M 突触连接

### 成绩
| 指标 | 数值 |
|---|---|
| 运动行为预测准确率 | **95%** |
| 具身化后行为准确率 | **91%** |
| 训练数据 / 奖励函数 / 梯度下降 / 反向传播 | **全为零** |

**论文原话（Princeton 出版物页）**：
> "create a leaky integrate-and-fire computational model of the entire Drosophila brain, **on the basis of neural connectivity and neurotransmitter identity**"
> "modelling brain circuits using **only synapse-level connectivity and predicted neurotransmitter identity** generates experimentally testable hypotheses and can describe complete sensorimotor transformations"

### 具体能力验证
- 激活**糖/水感知味觉神经元** → 准确预测哪些神经元响应味道、哪些是进食启动必需
- 激活**进食区神经元** → 预测哪些引发运动神经元放电（**用光遗传学实验验证**）
- 应用到**机械感觉回路** → 预测触角理毛回路的激活（准确描述不同机械感觉亚型的响应）

### ★ 对项目的启示：配方极简，可抄

主人项目的 `bio_brain.py` 已经有：
- ✅ 连接（`Tract.members` + `dynamics`）
- ✅ 带符号（INHIB_STRENGTH，小悠加的）
- ❌ **权重不是"突触数量"** —— 是随机初始化
- ❌ 神经元模型比 LIF 更复杂（但更复杂≠更好，见 §1）

**可抄的做法**：把 `dynamics` 从"随机初始化"改为**有依据的权重**——
哪怕只是"连接强度 ∝ 幂律分布"或"结构化稀疏"，也比均匀随机强。

## 3. 三个开源实现（可直接参考工程）

### 3.1 `eonsystemspbc/fly-brain`（**339 stars**，2026-03 建）

**Eon Systems 官方实现**，多后端对比：
```
Brian2 (CPU)      ← 神经准确性金标准（实现 Shiu et al. 的 canonical LIF）
Brian2CUDA        ← GPU
PyTorch           ← 
NEST GPU          ← 
Neuromorphic chips ← 类脑硬件
（新增 Brian2GeNN 作第 6 个后端）
```

**功能**：
- **激活任意神经元**（模拟光遗传激活，触发 Poisson 放电，可设两组不同频率）
- **沉默任意神经元**（模拟光遗传沉默）
- 输出：所有受影响神经元的 **spike times 和 rates**

**数据**：FlyWire **v783**（公开版）；旧版 v630 留在 `data/archive/` 供复现论文图

**工程细节（值得抄）**：
- spike timing 导出写到 **parquet**，且**放在计时区之外**，避免文件 I/O 污染 `sim_time`
- GeNN 在长批次运行时**分窗口刷新设备端 spike 记录**，该传输时间**单独计为 result collection** 而非 simulation time
- 环境用 conda：`environment.yml` / `environment-brian2genn.yml`

**★ 可抄点**：**"计时区与 I/O 分离"**——主人项目如果要做性能测量，必须学这个。

### 3.2 `erojasoficial-byte/fly-brain`（具身版）

**首个具身全脑脉冲仿真**：
- FlyWire v783：**138,639 神经元 / 15,091,983 条有向加权突触**
- **NeuroMechFly v2 / MuJoCo** 生物力学身体
- **多模态感觉处理**：视觉、嗅觉、味觉、飞行
- ★**Hebbian 突触可塑性**
- 多理论神经整合指标

**★ 可抄点**：**Hebbian 可塑**——这正是主人项目 `ALG-3 在线可塑` 想做的事，有现成参考。

### 3.3 `snedea/flybrain`（浏览器版，2026-03 建）

- **139,255 神经元 + 2.7M 连接**在 **Web Worker 里实时跑**
- LIF 模型
- 神经元按功能分组：**sensory / central / drives / motor**（依 FlyWire cell type 注释）
- 从 `heyseth/worm-sim`（302 神经元线虫）**fork 并放大 460 倍**
- 数据：`data/neuron_meta.bin.gz`，派生自 FlyWire Codex FAFB v783

**★ 可抄点**：**"神经元按 sensory/central/drives/motor 分组"**——与项目 `Tier` 概念一致，且**多了 "drives" 一类**（驱动力神经元，介于 central 和 motor 之间）。项目可以考虑加这一类。

### 3.4 相关：Loihi 2 类脑硬件实现（arXiv 2508.16792）
- 全 FlyWire connectome 塞进 **12 片 Intel Loihi 2**
- **比常规硬件的数值仿真快数个数量级**，且**活动越稀疏优势越大**
- 复刻 Brian2 的**双态 LIF + 不应期** + Poisson 输入神经元
- 教训：真实的生物回路是**稀疏、循环、不规则**的，**不适合稠密线性代数的常规计算方法**

## 4. ⚠️ 必须正视的反例：Brunton 团队的"数字斯芬克斯"

**这是本轮最重要的"泼冷水"，不写进文档就是自欺。**

### 反例内容
**Bing Wen Brunton 团队（University of Washington）2026-03 preprint**：
1. 取 **C. elegans 连接组（仅约 302 神经元）**
2. **接到与 Eon 完全相同的果蝇身体模型**（NeuroMechFly v2 + MuJoCo）
3. 用**深度强化学习**训练这个混合体（"worm brain, fly body"）
4. 他们称之为 **"digital sphinx"（数字斯芬克斯）**
5. **结果：它也能走**

### 质疑（Benjamin Cowley, CSHL 的表述）
> "the experiment enables researchers to ask **whether a randomly connected network could produce the same behaviors**"

**核心问题**：如果 302 个线虫神经元 + RL 也能产生走路，那么 Eon 的 91% 里：
- 多少来自**果蝇连接组的特异性**？
- 多少来自**RL 把脑缝到身体上**的贡献？

### 已知的方法论弱点（另一篇 substack 指出）
- Eon 的 **91% 行为准确率"其定义与测量方法未获独立验证"**
- Eon 最初presented为"**purely emergence from architecture — behavior arising directly from the copied structure, without AI training, prompts, or reinforcement learning**"
- 但质疑者指出：**把脑接到身体这个"缝合"过程本身可能需要 RL**

### ★ 对本项目的意义（重要）

主人项目**没有 RL 训练阶段**（NORM-3 无分离：训练是思考的副产品）。所以：

1. **好消息**：项目不走"RL 缝合"这条可疑路线，**不存在"成绩有多少来自 RL"的质疑**
2. **坏消息**：项目也**没有 Eon 那样的"91% 行为准确率"**可言——因为没有对照基准
3. **必须做的事**：确立**可验证的验收基准**，否则无法判断"结构编辑是否真的有效"

**小悠的建议**：项目的验收基准应该是**"跨输入的区分度"**（小悠之前定的），
而不是"像不像真实大脑"——后者没有 ground truth 可比。

## 5. ★ 综合结论：项目该改什么

### 5.1 诊断修正（重要）

| 小悠此前的判断 | 本轮修正 |
|---|---|
| 根因是"扩散无方向+无符号+无选择性" | **更深一层**：根因是**结构本身是随机初始化的（假结构）** |
| 解法："带符号 + 单向流"结构编辑 | 方向对，但**还缺"结构必须有信息"**这一步 |
| 判据："跨输入区分度" | 保留（这是唯一没有 ground truth 也能用的判据） |

**论文证据**：2404.17128 说 **0.1% 重连就破坏激活模式** ⇒ **随机结构 ⇒ 随机模式 ⇒ 无语义**。

### 5.2 下一步该做的（修正后的优先级）

| 优先级 | 动作 | 依据 |
|---|---|---|
| **P0-新** | **让 `dynamics` 摆脱"均匀随机"**——引入结构化权重（幂律分布 / 稀疏有向 / 基于角色的连接偏置） | 2404.17128：结构即信息 |
| **P0**（原有） | 继续 subtick + 交叉注意力 | 架构书 §6/§7 已定义 |
| **P1**（原有） | 编辑 4：运动端解耦（6 个挤一束） | 结构缺陷 |
| **P1**（原有） | η_v 接线（半成品） | 补完 FlyGM 第三要素 |
| **P2-新** | 参考 `snedea/flybrain` 的 **sensory/central/drives/motor 四分类**，考虑给项目加 "drives" 类 | 结构分组 |
| **P2-新** | 参考 Eon 的**"计时区与 I/O 分离"**，做性能测量时用 | 工程规范 |
| **P3-新** | 参考 `erojasoficial-byte/fly-brain` 的 **Hebbian 可塑**实现 | ALG-3 参考 |

### 5.3 一句话

> **项目不必先把动力学搞复杂**——论文明确说"拓扑 > 动力学"。
> 该做的是：**先把"结构"从随机变成有信息**，再谈动力学。
> 而"结构"的具体形态，Eon 的配方（突触数量当权重）已经给出了答案。
