# 亿级大脑工程计划（v6）

> **目标**：让仿生大脑从「百万神经元/4GB」扩展到「**亿级神经元/100GB+**」，且**内存占用可控**。
> **依据**：本文档的所有结论都来自实测（实验 1/2），不是推测。
> **硬件约束**：16GB RAM / RTX 4070 Ti 12GB / E盘 355GB 可用 / Windows。

---

## 一、问题的本质

### 当前参数量

| 规模 | 核心矩阵 | 内存 | 速度 |
|---|---|---|---|
| 26 万 | base+plastic+状态 | 1.0 GB | 71 ms/tick |
| 104 万 | 同上 | 4.0 GB | 420 ms/tick |
| **1000 万** | 同上 | **40 GB** ❌ | 装不下 |
| **1 亿** | 同上 | **400 GB** ❌ | 差得远 |

**核心矛盾**：参数量增长是 **O(n)**，但内存是**硬上限**。必须有"不在内存里的参数"。

### 关键洞察（来自实测）

1. **稀疏度是天然的**：实测活跃率稳定 **8%** —— 92% 的神经元在任一瞬间都是"沉睡"的
2. **沉睡的神经元不需要在内存里** —— 只要能在被激活时**快速载入**即可
3. **页缓存是免费的三层缓存**（实测第2次读快 3.8×）

## 二、实测数据（实验 1/2 结论）

### 实验 1：memmap 可行性（10.24 GB 矩阵）

| 操作 | 耗时 | 评价 |
|---|---|---|
| 创建 10.24GB 文件 | 14.2 s | 一次性 |
| **memmap 打开** | **0.001 s** | ✅ 秒开，不加载数据 |
| 随机写 1%（100MB） | 2.60 s | 39 MB/s |
| **随机读 1%（100MB）** | **0.164 s** | ✅ 可用于每 tick |
| 全量顺序扫描 | 4.20 s | 2.44 GB/s |

**结论**：10GB 矩阵**完全不占内存**即可使用。

### 实验 2：访问模式优化

| 场景 | 耗时 | 结论 |
|---|---|---|
| 第 1 次冷读 1% | 177 ms | 从磁盘 |
| **第 2 次热读 1%** | **47 ms** | **页缓存加速 3.8×** |
| 集中布局读 | 42 ms | 局部性有效 |
| 逐行读 2000 行 | 9 ms | fancy index 高效 |
| 分片加载 10 片 | 231 ms | 适合"少数脑区活跃" |

**结论**：**热数据会自然加速**，符合"激活度分级加载"的设计初衷。

## 三、架构设计：三层存储（真正落地分片）

### 设计原则

```
内存中的数据 ∝ 活跃规模（不是总规模）
磁盘中的数据 ∝ 总规模
```

### 三层结构

| 层 | 介质 | 内容 | 访问延迟 | 容量 |
|---|---|---|---|---|
| **L0 热** | RAM（numpy 稠密） | 当前活跃神经元（~8%） | ~0.1 μs | 2-6 GB |
| **L1 温** | RAM（memmap 页缓存） | 近期访问过的 | ~10 μs | 页缓存自动管 |
| **L2 冷** | NVMe（memmap 文件） | 全部参数 | ~100 μs | **无上限** |

### 关键机制

1. **神经片（Fragment）**
   - 把神经元按"神经组"分片，每片独立文件
   - 片大小可配（默认 10 万神经元 ≈ 100 MB）
   - **只有活跃片被 memmap 到内存，冷却后自动释放**

2. **激活度驱动的迁移**
   ```
   每 N 轮：
     · 统计每片的激活频率
     · 高频片 → 预加载到 L0（稠密数组）
     · 低频片 → 只保留 memmap 句柄（L2）
     · 中频片 → 留在页缓存（L1）
   ```

3. **睡眠期深写**
   - 睡眠时把 L0 的改动**批量写回** L2 文件
   - 顺序写（快），避免随机写

4. **页缓存预热**
   - 用 harness 的空闲时间**预取**可能出现的热片
   - 这是规范里"静默态预取减少响应态 I/O 等待"的真正实现

### 实验 3：千万级大脑实测（1000 万神经元 / 10.24 GB）

| 指标 | 结果 |
|---|---|
| 内存实际占用 | **0.819 GB**（4 片） |
| 内存节省 | **92.0%** |
| 数据/内存比 | 10.24 GB / 16 GB RAM |
| 问题 | 每轮 **4294 ms**（太慢） |
| 原因 | 随机激活碰到所有 50 片 → 每轮换片 1000 次 |

**结论**：内存问题**解决了**（92% 节省），但**速度问题暴露了** —— 见实验 4。

### 实验 4：局部性优化（决定性发现）

| 激活模式 | 耗时 | 加速 |
|---|---|---|
| 纯随机 | 2556 ms | 基线 |
| **局部（集中 10% 的片）** | **82 ms** | **31.2×** 🚀 |
| 排序索引 | 1373 ms | 1.9× |
| 片内集中 | 172 ms | 14.9× |

**关键结论**：
> **只要激活有局部性，memmap 就接近内存速度。**

这直接决定了架构设计：**必须做"功能分区"** ——
把语义/功能相似的神经元分配到**同一片**，让激活自然聚焦在少数片上。

### 由此确定的最终架构

```
神经元分配：按"功能簇"分片（相似神经元同片）
    ↓
激活模式：天然局部（思考某主题 → 只点亮相关片）
    ↓
I/O：只需载入少数片（而非全部）
    ↓
结果：内存省 90%+，速度接近内存版
```

**这不是妥协，是仿生**：人脑本身就有功能分区（布罗卡区、视觉皮层…）。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 随机访问慢 | tick 变慢 | 局部性布局 + 页缓存预热 |
| 磁盘 IO 抖动 | 思考卡顿 | 预取 + 异步写回 |
| 分片管理开销 | 内存/CPU 浪费 | 句柄池 + 懒加载 |
| 睡眠写回丢数据 | 学到的没了 | 双缓冲 + 校验 |
| 页缓存被挤占 | 热数据被换出 | 锁定热片（VirtualLock） |
