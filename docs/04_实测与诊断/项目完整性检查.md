## 5. 建议的下一步优先级

| 序 | 动作 | 理由 | 工作量 |
|---|---|---|---|
| **P1** | **同步 `code/` → `repo/src/` 并提交** | D1：git 里的代码 ≠ 跑的代码，**这是最大的完整性风险**（一旦误回滚 `repo/src` 会丢掉 v3.1~v3.4 全部修复） | 小（1 小时） |
| **P2** | **统一主线大脑**（合并 CogVec / Conductor，或明确 Conductor 为唯一主线） | 解 P-ARCH-15/16/2 的前置；D 专家已证两套大脑是闭卷问答的首要阻塞 | 中（1~2 天） |
| **P3** | **修 P-ARCH-15/16**（工作记忆 + 记忆库读回路） | 唯一两个未修的 **P0**；不修则"记得次数不记得内容" | 中 |
| **P4** | **动 P-TOPO-5/6/7**（束内全连接 / 横向选择性 / 门控冲突） | 架构书判定为**唯一被证明有效的缺陷类别**；是"选择性路由"的结构前提。**务必先改架构书**（铁律 A1） | 大（多轮迭代） |
| **P5** | 修 P-ARCH-14（合并两套 HTTP 服务） | 剩余 P0，风险低于 P3 | 中 |
| **P6** | 补 `flask` / `bs4` 依赖 | 让 API 服务与抓取可用 | 极小 |
| **P7** | 补 D4（bot `STATUS.json`）/ D6（扩展名）等文档小缺口 | 卫生 | 极小 |

> **顺序理由**：P1 是**风险**（会丢代码），先做；P2→P3 是**功能阻塞链**（不统一主线，修记忆缺陷等于修两遍）；
> P4 是**架构本体**，风险最大，必须先改架构书再动代码。
