# 第 1 章 · 项目定位

## 1.0 一句话定位（2026-09-19 澄清）

> **本项目 = 生物启发的连续值向量神经元网络**
> （biologically-inspired continuous-valued vector-neuron network）

**与 SNN 的关系**：**不是 SNN**，但是**SNN 的连续松弛版本 + 注意力机制**。
- 借用了 SNN 的**生物结构直觉**（树突/胞体/轴突、束、分层、可塑性、睡眠巩固）
- 放弃了脉冲的**离散性**（不用 0/1 spike、不用 LIF 膜电位方程）
- 改用**连续向量**（16 维 soma/axon）+ **注意力路由**

**判定依据（实测）**：SNN 三大标准全部不符 —— 见 §2.6。
**借鉴方案**：见 `docs/02_计划/SNN借鉴方案设计.md`（ALG-20/21/22）

## 1.1 一句话

构建一个**仿生认知架构**——AI 像人脑一样**持续思考、思考中学习、睡眠中巩固**，
而不是"先训练后使用"的语言模型。

## 1.2 与主流 LLM 的根本区别

| | 主流 LLM | 本项目 |
|---|---|---|
| 运行形态 | 被问才启动，答完就停 | **思考流永不停止**（NORM-1） |
| 学习 | 训练/推理分离 | **训练是思考的副产品**（NORM-3） |
| 输入输出 | 外挂 API | **感觉端/运动端**（NORM-2） |
| 权重 | 全量微调 | 只动可塑量，睡眠期合并（NORM-5） |

## 1.3 硬件目标

RTX 4070 Ti 12GB / 16GB RAM / NVMe / Windows

## 1.5 ★架构愿景：矩阵流双向翻译器（2026-09-19 新增）

### 1.5.1 完整链路（主人的设想）

```
① 输入转化
   传感器 / 视频流 / 电压数据
        ↓ 解析
   矩阵流（矩阵序列）
        ↓
② 神经处理（低成本三支柱）
   · 时空间梯度稀疏发散
   · 多层神经元群组
   · 群组 KV 缓存归一化
        ↓
③ 自学习
   · 检查「对齐度」→ 判断输入陌生程度
   · 按陌生度反向调节（见 1.5.3）
        ↓
④ 输出转化
   神经活跃 → 输出端口持续传播矩阵流

**一句话**：**把项目做成"矩阵流的双向翻译器"** ——
任意模态 → 矩阵流 → 神经 → 矩阵流 → 任意模态。

### 1.5.3 ★关键裁决：「反向传播」用三因子规则替代

主人的"反向传播"（用对齐误差指导学习）**不需要传统 BP**：

| 路径 | 符合 NORM-3？ | 可行性 | 说明 |
|---|---|---|---|
| A. 传统 BP | ❌ 违反（需停机训练 + 破坏因果） | 需引入 torch | 推翻项目定位 |
| **B. 三因子局部规则** | ✅ **符合** | **可立即实施** | `Δw = η·e(t)·M(t)`，M(t) 来自对齐误差 |
| **C. 对齐误差作调制** | ✅ 符合 | 可实施 | 对齐低→加强学习；对齐高→减弱 |

**决议**：**用 B/C，不用 A**。
**意图（用误差指导学习）完全可由三因子规则实现**，且**内存 O(1) vs BPTT 的 O(T)**。

## 2.3 ★奖励与路径形成实测（2026-09-19 新增）

### 2.3.1 铁证：唯一的学习机制里没有奖励

```python
# ── bio_brain.py 的 update_structure（项目唯一的结构学习机制）──
act = {i: self.neurons[i].activity for i in active_set}   # ← 只取"活动"
...
    ai = act.get(i, 0.0)      # 前神经元活动
    aj = act.get(j, 0.0)      # 后神经元活动
    # Δw = η·a_i·a_j          # ← 纯 Hebbian：共激活 → 加强
```

**关键**：`Δw = η·a_i·a_j` **只有 `a`（活动），没有任何 `reward`/`outcome` 项**。

> **不管这个念头带来好结果还是坏结果，只要两个神经元同时活跃，连接就被加强。**

### 2.3.2 `outcome` 存在但从未流向突触

| 位置 | 现状 |
|---|---|
| `self_training.py:46` | `outcome: float # 结果好坏（来自可靠来源）` ✅ 字段存在 |
| `self_training.py:57` | `RELIABLE_SOURCES = {"oracle","user_action","outcome"}` ✅ 白名单存在 |
| `server.py:244` | `outcome=raw_conf` ⚠️ **喂的是"自信度"，不是"对错"** |
| `server.py:246` | `record_outcome(task_type, success=(raw_conf>0.45))` ⚠️ 存进 `SelfModel` 就不管了 |
| **`update_structure`** | ❌ **完全没读 `outcome`** |

**结论**：`outcome` 只进了 `SelfModel`（统计用）和 `ExperienceBuffer`（存档用），
**对网络连接没有任何影响** —— **奖励与学习之间是断链的**。

### 2.3.3 当前能形成什么 vs 不能形成什么

| 能力 | 需要什么 | 现状 |
|---|---|---|
| "A 和 B 经常一起出现" | Hebbian | ✅ **有**（共现关联） |
| "这条路径能解决问题" | **奖励信号** | ❌ **没有** |
| "失败的路要削弱" | **惩罚信号** | ❌ **没有** |
| "延迟奖励归因到之前动作" | **资格迹** | ❌ **没有** |
| "试错探索新路径" | **探索/利用机制** | ❌ **没有** |

> **净效果**：网络**只会"把同时出现的东西绑在一起"**，
> **不会"把能解决问题的路走通"** —— **这就是"不能形成路径"**。

### 2.3.4 更严重：现有 `outcome` 本身是假的

```python
# ── server.py:244-246 ──
outcome=raw_conf,                                     # 用"自信度"当"结果好坏"
record_outcome(task_type, success=(raw_conf > 0.45))  # 自信 > 0.45 就算"成功"
```

**三层问题**：
1. `raw_conf` 是**网络自己的置信度**，不是**外部对错判定**
2. 项目**没有生成能力** → 没有 oracle 能判对错 → `raw_conf` 实质是**自评**
3. **NORM-6 明确禁止自评**，但它被贴上了 `source="outcome"` 的**合法标签**

> **这是"用合法标签包装自评信号"** —— **违反 NORM-6 的精神**。

### 2.3.5 四层缺陷汇总

| 层 | 缺陷 | 后果 |
|---|---|---|
| **L1** | 无奖励信号 | 无法区分"好路径/坏路径" |

| **L4** | 无探索机制 | 不会试新路径，只在已有连接打转 |

## 2.7 ★DeepSeek KV Cache 借鉴实测（2026-09-19 新增）

> 论文：**DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression**（arXiv:**2609.19969**，2026-09-17）
> 完整设计见 `docs/02_计划/DeepSeek-KVcache借鉴方案设计.md`

### 2.7.1 论文核心（实证摘录）

| 指标 | 数值 |
|---|---|
| 单 token 全局 KV 占用 | **890 bytes** |
| vs DeepSeek-V4-Flash | **1/4** |
| vs DeepSeek-V1 | **1/437** |
| 持久化 KV | **1/8** |
| Decode FLOPs | **随上下文长度近乎恒定** |

**三大机制**：
1. **CSA2 三模式**：`Full`（算全部）→ `Reindex`（复用 KV，重排索引）→ `Reuse`（白嫖索引）
2. **Hierarchical Sparse Indexer**：第一层全范围粗筛建**候选池** → 后续层**池内精排**（成本与长度解耦）
3. **FP4 KV + SWA Bounded Replay**

### 2.7.2 项目对照（实测发现的三个问题）

| 项 | 项目实测 | DeepSeek 对照 | 差距 |
|---|---|---|---|
| **注意力打分** | `BIND` = **1160 次打分**，占 compute **26.6%** | 三模式把大部分层降为 `Reuse` | **项目是"每束都 Full"** |
| **束间冗余** | **T65↔T66 key 余弦 = 1.00**（T67↔T68 同） | 跨层 KV 共享 | **100% 重复计算** |
| **稀疏化失败** | 限制自身束 → **仅 5/208 = 2.4%** 一致 | **Hierarchical Indexer** | **这是正解** |

### 2.7.3 ★最重要的发现：架构层缺失

> **DeepSeek 的 KV cache 思路本质是「分层复用」：**
> **`Full` 层产出 → `Reindex` 层重排 → `Reuse` 层白嫖**
>
> **而项目现在的做法是"每束都 Full"** —— 这是**架构层缺失**，不是参数问题。

**这解释了三个历史困惑**：
1. 为什么 `BIND` 占 26.6%？→ **重复计算**（每束独立算）
2. 为什么 `T65↔T66` key 余弦 = 1.00？→ **两个束在算同一件事**
3. 为什么稀疏化只有 2.4% 一致？→ **硬性裁剪 vs "粗筛+精排"**

### 2.7.4 ★2.4% 陷阱的正解（关键）

| 项目失败做法 | DeepSeek 正解 |
|---|---|
| **硬性限制在自身束内** → 2.4% 一致 | **全范围粗筛候选池 → 池内精排** |
| 丢失跨束目标（真值 top-K 仅 31.2% 在自身束内） | **保留跨束可能**（粗筛是全范围） |
| 一次性决定 | **两阶段**：粗筛 + 精排 |
| 成本随规模增长 | **候选池固定 → 成本与规模解耦** |

> **原文**："the first layer assigned to Full Mode constructs a **candidate pool** that later
> re-indexing layers use as their **search domain**... the number of positions scored per query
> by each subsequent indexer is **bounded independently of context length**."

**新增缺陷**：
| # | 缺陷 | 影响 | 优先级 |
|---|---|---|---|
| **P-ARCH-24** | ★★ **无跨层/跨束复用抽象**（每束都 Full） | BIND 26.6% 冗余；T65/T66 100% 重复 | **P1** |

### ALG-18 工作记忆（2026-09-19 实施，v3.10）

**治 P-ARCH-15「记得次数不记得内容」**。实测证据：不同历史（猫/狗/量子纠缠）→ 探测同一输入「猫」，输出差异仅 **0.0001**；而「无历史 vs 有历史」Δ≈0.13 → **只区分第几次输入，不区分输入了什么**。

```
注入信号 = α·encode(当前) + β·Σ wᵢ·encode(第 i 轮)
           当前为主(α)      历史为辅(β)，wᵢ 随时间衰减

实现（bio_brain.py · class WorkingMemory）：
    WM_SIZE  = 4     最近 4 轮编码（不是 activity！）
    WM_DECAY = 0.5   wᵢ = DECAY^i（越近权重越大）
    WM_ALPHA = 1.0   当前输入权重
    WM_BETA  = 1.5   历史混合权重（α=1 时历史占 ~25% 注入方差）

    think() 第 1 步：vec = brain._encode_with_memory(text)
        ├─ 读旧栈 → memory.blend(vec)   ← 【本 tick 只读】（NORM-4）
        ├─ 注入 + 归一化回原量级
        └─ 注入之后 → memory.push(vec)  ← 写在本 tick 之后才可见
```

**三条硬约束**（违反任一即无效，均有历史实证）：
1. **只改输入侧**。权重层改动已四次迭代证明无效（见 `docs/04_实测与诊断/结构可塑四次迭代教训.md`）；本改动**不碰** `update_plasticity` / `update_structure` / `W_*`。
2. **不用 activity 残留当记忆**。现有做法（`self.active` 跨 `think()` 不清空 → 激活残留）已证无效：活性被 `DECAY=0.9` + 饱和抑制抹平，且残留**与语义无关**（只反映「刚活跃过」）。
3. **注入向量整体 L2 归一化**。`encoder.encode()` 输出本是单位向量；若直接 `α·v + β·Σwᵢvᵢ`，向量模长随轮次漂移 → 点火幅度变化 → 同样本不同轮不可比。混合后归一化，保证「只有方向带信息」。

**注意**：历史项是**未归一的原始编码和**（方向加权平均），不是把历史编码逐个归一化再平均 —— 后者会丢掉「历史向量相互抵消」这一信息（猫 + 反猫 = 无历史偏好）。

**回退**：`BIO_WORKMEM=0` → `_encode_with_memory()` 原样返回当前编码，行为与 v3.9 完全一致（默认 `1`）。

# 第 6 章 · ★核心认知（血泪规律）

## 6.1 拓扑层有效，权重层无效

| 层 | 改什么 | 结果 |
|---|---|---|
| **拓扑层** ✅ | **谁连谁 / 方向 / 符号** | 带符号✓ 单向流✓ 运动端解耦✓ **key 派生✓** |
| **权重层** ❌ | 权重多大 / 什么分布 / 怎么学 | **五次尝试全部无效或退化** |

**为什么**：拓扑决定「**信息怎么流**」，权重只决定「流多快多强」。
本项目的问题是"不同输入流到同一个地方"——是**流向**问题。

**行动规则**：动手前先问「我改的是谁连谁，还是连多重？」

## 6.2 ★第二规律：没有奖励，就没有路径（2026-09-19 新增）

| 机制 | 项目现状 | 后果 |
|---|---|---|
| **Hebbian**（共激活→加强） | ✅ 有 | 能绑定"共现"，**不能走通"有效"** |
| **奖励信号** | ❌ **无**（`update_structure` 里 `Δw` 只有 `a_i·a_j`） | 分不出好坏路径 |
| **惩罚信号** | ❌ 无 | 失败的路**不会**被削弱 |
| **资格迹** | ❌ 无 | 延迟奖励**无法归因** |
| **探索机制** | ❌ 无 | 不会试新路 |

**与第一规律的关系（重要）**：
> 第一规律说「**改拓扑有效，改权重无效**」——这是**"信息流"层**的结论。
> 第二规律补上**"选择"层**：**即使拓扑对了，没有奖励也无法"选出"哪条路是对的。**

**两者不矛盾，而是层次不同**：
```
第 1 层（拓扑）：信息怎么流        ← 已解（拓扑层改动有效）
第 2 层（奖励）：哪条路该被强化    ← ❌ 未解（本规律）
第 3 层（权重）：连接多强          ← 已证无效（不要碰）
```

**行动规则**：动手前先问三句话 ——
1. 「我改的是谁连谁（拓扑），还是连多重（权重）？」→ 只动拓扑
2. 「这个改动有奖励信号参与吗？」→ **没有奖励的"学习"只是在绑定共现**
3. 「奖励从哪来？是外部可验证的吗？」→ 必须过 NORM-6（自评禁用）

**★历史教训的重新解读**：
> 项目此前所有"权重层失败"（Hebbian 饱和、Oja 削弱、L1 归一化无效）
> **不只是"改错了层"，更是"在一个没有奖励的系统里优化无目标的相关性"**——
> 无论如何调参，**没有目标信号的学习必然收敛到无意义的不动点**。

## 6.3 校准陷阱

> **判定修复是否成功，唯一可信指标是「跨输入的区分度」。**
> 峰值高、饱和数 0，都不能说明任何事。
> 且必须检查"噪声激活 < 有意义输入"，否则可能是**能量驱动**而非语义驱动。

## 6.4 沉默缺陷的教训

**两次栽在"看似活着实则空转"**：
1. `compute` 空转（soma/axon 恒为 0）—— 所有诊断只测 `activity`，没人查 `compute` 的产物
2. `_attn_out` 被提前清空 —— 学习拿不到数据

> **教训：「看起来在跑」≠「真的在跑」。必须对每条数据通路都有断言。**

## 8.4 ★R1 修复设计（v3.1）：真存盘

### 问题回顾

`save()` 只存元数据，**丢失全部神经状态与记忆库内容** → 重启即失忆。

### 设计：分层持久化

```
state 文件结构（JSON + 二进制分离）
├── meta.json          ← 元数据（版本/seed/tick/自模型统计）
├── neurons.npz        ← ★神经状态（numpy 压缩）
│     base / plasticity / activity / soma / axon / dendrite
│     importance / eta
├── tracts.npz         ← ★连接（dynamics / key / value / w_fast / w_slow）
│     + tier（字符串，存 meta）
├── libraries.json     ← ★分层状态（tier / size_bytes / hot_score）
├── memory.jsonl       ← ★记忆库内容（Experience 逐条）  ← 之前完全丢失
├── collective.json    ← 集体层（原来有）
└── attn.npz           ← ★投影矩阵 W_q/W_k/W_v/W_o
```

### 为什么用 npz + json 分离，而不是一个大 JSON

| 理由 | 说明 |
|---|---|
| **体积** | 神经状态是浮点矩阵，JSON 化会膨胀 3-5 倍且损精度 |
| **二进制安全** | 浮点用 JSON 存会丢精度（`float` 序列化问题） |
| **增量友好** | 记忆库用 `jsonl` 可追加，不必整体重写 |
| **兼容** | 旧 `state.json` 仍能读（向后兼容：缺失字段用默认值） |

### 兼容策略（重要）

```
load() 逻辑：
  1. 若无 meta.json → 尝试按**旧格式**读单个 json（向后兼容）
  2. 若 meta 的 version < 3.1 → 只恢复能恢复的字段，其余用默认值
  3. 若有神经元数不匹配 → 警告并按最小数量恢复（不崩）
```

> 信息在**最上游**就丢了，下游任何优化都补不回来（这是把输入排 P0 的唯一理由）。

### 10.4.1 缺陷总表

| # | 缺陷 | 实测证据（修复前） | 影响 | 优先级 |
|---|---|---|---|---|
| **P-INPUT-1** | ★★ **入口硬截断 8 倍** | `SensoryPort(dim=16)` 而 `get_encoder().dim=128` → `raw[:16]` 把 128 维**截断到 16 维**；`|v|` 从 **1.0000 塌到 0.3804**（**输入能量只剩 14%**，86% 的语义向量被静默丢弃） | 语义编码器（bge-small-zh，cos(猫,猫咪)=0.919）的全部工作在入口被丢掉 86% | **P0** |

### 10.4.2 架构裁决（本节即为 §5.1 感觉端的**权威补充**）

| 条款 | 内容 | 理由 |
|---|---|---|
| **C1** | **感觉端维度 MUST ≥ 编码器维度**。压缩只许发生在**可逆/保距**的投影里，**严禁用切片截断**（`raw[:d]`）丢维度 | 切片既不保距也不保能量（实测只剩 14% 能量），是**静默信息销毁** |
| **C2** | **点火强度 MUST 保留分布**：动态归一（能量阈值自适应），严禁静态 `tanh(proj)` 缩小到与下游门槛错配的量级 | 「强响应多留、弱响应少留」是"耳朵"的最低要求 |
| **C3** | **点火 MUST 带符号**（`queue_ignition(nid, a)` 而非 `(nid, abs(a))`） | 抑制性投射是 §6「带符号突触」的前置；符号在入口丢失后无处可补 |
| **C4** | **稀疏 MUST 按"能量覆盖"而非"固定比例"**：保留累计能量达 `ENERGY_COVER` 的神经元 | 固定 top-50% 会保留陪跑者、砍掉真信号；按能量自适应让强弱输入用不同的 k |
| **C5** | **回退开关 MUST 存在**：`BIO_INPUT_V2=0` → 逐位回到 V1 行为（含 `abs()`） | 输入模式一变，下游（扩散/注意力/可塑）全部输入随之改变，必须可一键回退做 A/B |
| **C6** | ⚠️ **输入修好后，下游参数 MUST 重标定**（但**不在 I-1 内改动**）：`PLASTIC_THRESHOLD` / `SPREAD_*` / `MSG_GAIN` / `ATTN_GAIN` / 各阈值均按旧点火量级（max 0.19）标定；V2 点火量级升到 max≈0.5 → 激活峰值、可塑触发率、扩散饱和都会变 | 与「修好 compute 后要重标定」同一类连锁。I-1 只修入口，**下游重标定另开任务** |

### 10.4.3 附：束 key 结构派生退化（P-TOPO-6 的根因补充，未修）

实测（`diag_entry_budget.py` ⑧）：`_derive_tract_key()` 只按**角色计数**求和 →
