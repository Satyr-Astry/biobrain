# 第 1 章 · 项目定位

## 1.1 一句话

构建一个**仿生认知架构**——AI 像人脑一样**持续思考、思考中学习、睡眠中巩固**，
而不是"先训练后使用"的语言模型。

## 1.2 与主流 LLM 的根本区别

| | 主流 LLM | 本项目 |
|---|---|---|
| 运行形态 | 被问才启动，答完就停 | **思考流永不停止**（NORM-1） |
| 学习 | 训练/推理分离 | **训练是思考的副产品**（NORM-3） |
| 输入输出 | 外挂 API | **感觉端/运动端**（NORM-2） |
| 权重 | 全量微调 | 只动可塑量，睡眠期合并（NORM-5） |

## 1.3 硬件目标

RTX 4070 Ti 12GB / 16GB RAM / NVMe / Windows

## 1.4 ★实际任务合理性评估（2026-09-18 新增）

**诚实的评估：本项目目前"没有实际任务"。**

| 问题 | 说明 |
|---|---|
| **无服务对象** | 从头到尾没有"它在为谁服务"。优化目标（dmin/peak/tier）都是**自己造的指标** |
| **无验收基准** | 没有 ground truth 可比（不像果蝇项目有真实大脑数据对照） |
| **代码里早有的任务入口，都没在用** | `autonomous_agent --goal` / `llm_distiller --topic` / `batch_learn` |

**已有能力 vs 可用性**：

| 能力 | 代码状态 | 实际可用性 |
|---|---|---|
| 语义编码 | ✅ bge-small-zh 已加载 | ✅ 可用 |
| 思考流 | ✅ 可持续跑 | ⚠️ 但无外部输入源 |
| 记忆存储 | ✅ ExperienceBuffer | ❌ **只写不读**（think 无召回） |
| 睡眠巩固 | ✅ 已实现 | ❌ **从不自动触发** |
| 输入连续性 | ❌ **无工作记忆** | ❌ **记得次数不记得内容** |
| 生成（说话） | ❌ 无后端 | ❌ **诚实返回 None** |

**结论**：
> 项目**具备了"内部机制"，但缺少"实际任务"与"任务驱动的验收"**。
> **这是当前最本质的问题**——不是机制不够，而是**没有目标**。

**三类可选实际任务**（待主人定）：
| 类型 | 内容 | 判据 |
|---|---|---|
| **A 学习型** | 学一个主题，之后能答 | 闭卷测试答对率 |
| **B 记忆型** | 记住偏好，下次不用重说 | 复述/检索准确率 |
| **C 工具型** | 用工具查真实问题并回答 | 答案可验证 |

**硬约束**：任何"要它说话"的任务，**必须先接生成后端**（架构书 §1.5 已提）。

# 第 3 章 · 核心数据结构

## 3.1 四级组织

```
Library（神经库，一级存储单位，携带 tier）
  └─ Group（神经组，功能团块）
       └─ Tract（神经束，一起激活的通路，携带 tier/key/value）
            └─ Neuron（神经元 = 向量组）
```
**重叠规则**：一个神经元可属多个束（`tract_ids: Set`）——跨束路由的基础。

## 3.2 Neuron（`bio_brain.py`）

| 字段 | 类型 | 含义 |
|---|---|---|
| `dendrite` / `soma` / `axon` | `ndarray(16)` | 树突场 / 胞体态 / 轴突场 |
| `base` | `ndarray(256)` | 主体权重（16×16 扁平） |
| `plasticity` / `plasticity_pending` | `ndarray(256)` | 在线可塑 + **延迟提交缓存**（NORM-4） |
| `activity` | `float` | 激活度 ∈[0,1]（**主数据通路**） |
| `importance` | `float` | Fisher 重要性（EWC 用） |
| `tract_ids` | `Set[int]` | 所属束 |
| `role` | `str` | sensory / inter / drives / motor |
| `eta` | `ndarray(4)` | ★固有描述子 η_v（**已声明未接线**，见 §8） |

## 3.3 Tract

| 字段 | 含义 |
|---|---|
| `members` / `dynamics` | 成员 / 协同矩阵 |
| `key` / `value` | ★路由标识（**由角色派生**，非随机）/ 读出内容 |
| `tier` | sensory / inter / drives / motor（信息流方向约束） |
| `w_fast` / `w_slow` / `w_pending` | 结构可塑字段（**默认关闭**，见 §8.4） |
| `row_budget` | 突触稳态预算（自适应） |

## 3.4 Library

| 字段 | 含义 |
|---|---|
| `group_ids` / `activation` | 组成 / 激活度 |
| `tier` | VRAM / RAM / NVME（三级驻留） |
| `size_bytes` | 字节数（调度搬运代价） |
| `hot_score` / `act_history` | 热分数 EMA / 激活历史（热存储 + 预取） |

# 第 5 章 · 时序架构（subtick）

## 5.1 从 whole-tick 到 subtick（v1.9 完成）

**旧问题（whole-tick）**：一个 tick 串行 6 件事、共用同一 activity 快照 →
① 三个时间尺度混叠 ② 同 tick 读改写纠缠 ③ 注意力与扩散耦合

**新架构（9 相位，读写严格分离）**：
```
COMMIT → DECAY → IGNITE → SPREAD×n → BIND → INTEGRATE → EMIT → PLASTIC → SCHEDULE
 提交可塑   只改act   点火    扩散(可多步)  只读     唯一写soma   轴突   写pending   调度
```

| 相位数据流 | 读写 |
|---|---|
| activity | SPREAD 读/写 |
| soma | **BIND 只读** → **INTEGRATE 写** |
| axon | EMIT 写 |
| pending | PLASTIC 写，COMMIT 提交 |

**兼容开关**：`BIO_SUBTICK=0` 走旧路径；默认 1 走相位化。

# 第 6 章 · ★核心认知（血泪规律）

## 6.1 拓扑层有效，权重层无效

| 层 | 改什么 | 结果 |
|---|---|---|
| **拓扑层** ✅ | **谁连谁 / 方向 / 符号** | 带符号✓ 单向流✓ 运动端解耦✓ **key 派生✓** |
| **权重层** ❌ | 权重多大 / 什么分布 / 怎么学 | **五次尝试全部无效或退化** |

**为什么**：拓扑决定「**信息怎么流**」，权重只决定「流多快多强」。
本项目的问题是"不同输入流到同一个地方"——是**流向**问题。

**行动规则**：动手前先问「我改的是谁连谁，还是连多重？」

## 6.2 校准陷阱

> **判定修复是否成功，唯一可信指标是「跨输入的区分度」。**
> 峰值高、饱和数 0，都不能说明任何事。
> 且必须检查"噪声激活 < 有意义输入"，否则可能是**能量驱动**而非语义驱动。

## 6.3 沉默缺陷的教训

**两次栽在"看似活着实则空转"**：
1. `compute` 空转（soma/axon 恒为 0）—— 所有诊断只测 `activity`，没人查 `compute` 的产物
2. `_attn_out` 被提前清空 —— 学习拿不到数据

> **教训：「看起来在跑」≠「真的在跑」。必须对每条数据通路都有断言。**

## 8.5 ★R1 修复设计（v3.1）：真存盘

### 问题回顾

`save()` 只存元数据，**丢失全部神经状态与记忆库内容** → 重启即失忆。

### 设计：分层持久化

```
state 文件结构（JSON + 二进制分离）
├── meta.json          ← 元数据（版本/seed/tick/自模型统计）
├── neurons.npz        ← ★神经状态（numpy 压缩）
│     base / plasticity / activity / soma / axon / dendrite
│     importance / eta
├── tracts.npz         ← ★连接（dynamics / key / value / w_fast / w_slow）
│     + tier（字符串，存 meta）
├── libraries.json     ← ★分层状态（tier / size_bytes / hot_score）
├── memory.jsonl       ← ★记忆库内容（Experience 逐条）  ← 之前完全丢失
├── collective.json    ← 集体层（原来有）
└── attn.npz           ← ★投影矩阵 W_q/W_k/W_v/W_o
```

### 为什么用 npz + json 分离，而不是一个大 JSON

| 理由 | 说明 |
|---|---|
| **体积** | 神经状态是浮点矩阵，JSON 化会膨胀 3-5 倍且损精度 |
| **二进制安全** | 浮点用 JSON 存会丢精度（`float` 序列化问题） |
| **增量友好** | 记忆库用 `jsonl` 可追加，不必整体重写 |

### 兼容策略（重要）

```

  1. 若无 meta.json → 尝试按**旧格式**读单个 json（向后兼容）
  2. 若 meta 的 version < 3.1 → 只恢复能恢复的字段，其余用默认值
  3. 若有神经元数不匹配 → 警告并按最小数量恢复（不崩）
```
