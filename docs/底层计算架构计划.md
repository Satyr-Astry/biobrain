## 0. 核心命题

> **AI 不是"一个模型"，而是一套"神经组织"，按激活度在不同存储层级间流动；而思考流永不停止。**

三件事必须落成可算的：
1. **组织**：神经元(向量组) / 神经束 / 神经组 / 神经库（**可重叠**）
2. **激活度**：每级组织"有多活跃"的量化 + 聚合
3. **分级加载**：按激活度把组织放进 VRAM / RAM / NVMe

## 1. 数据结构

### 1.1 神经元 = 向量组
```python
class Neuron:
    # 一个神经元不是标量，是多个向量(多隔室)
    dendrite: Tensor      # 树突场 (接收)     shape: [d_in]
    soma:     Tensor      # 胞体态 (整合)     shape: [d_state]
    axon:     Tensor      # 轴突场 (输出)     shape: [d_out]
    # 可塑量(临时,思考中更新)
    plasticity: Tensor    # 与上面同形的增量
    # 激活度
    activity: float       # 本步激活度 [0,1]
    
    # 归属(关键: 可属多个束!)
    tracts: list[TractRef]   # 该神经元参与的神经束(多个)
```

### 1.2 神经束 / 组 / 库
```python
class Tract:                     # 神经束: 一起激活的一组神经元
    neurons: list[NeuronRef]     # 成员(引用,非拥有)
    activation: float            # 束激活度 = 成员聚合
    pattern: Tensor              # 该束的"协同模式"(一起怎么发火)

class Group:                     # 神经组: 功能团块
    tracts: list[TractRef]       # 成员束(可重叠)
    activation: float            # 组激活度
    function: str                # 语义标签: "vision"/"language"/"tool-use"

class Library:                   # 神经库: 最大单位,一级存储单位
    groups: list[GroupRef]
    activation: float
    storage_tier: str            # 当前驻留在哪一层: vram/ram/nvme
    size_bytes: int
```

### 1.3 全局组织表
```python
class NervousSystem:
    neurons: dict[NeuronID, Neuron]
    tracts:  dict[TractID, Tract]
    groups:  dict[GroupID, Group]
    libraries: dict[LibID, Library]
    
    # 反向索引(重叠必需)
    neuron_to_tracts: dict[NeuronID, set[TractID]]
    tract_to_groups:  dict[TractID, set[GroupID]]
    group_to_libs:    dict[GroupID, set[LibID]]
    
    # 存储管理
    tier_manager: TierManager
```

## 2. 激活度算法（调度的心脏）

### 2.1 神经元激活度
神经元是向量组，激活度取**多隔室能量聚合**：
```
activity(n) = σ( w_d·||dendrite|| + w_s·||soma|| + w_a·||axon|| )
```
- `||·||` 可取 L2 范数（或能量/熵）
- `w` 是各隔室权重（可学习）
- σ 归一化到 [0,1]

### 2.2 逐级聚合
```
束激活度:   Tract.activation  = aggregate(成员神经元 activity)   # 加权和 / 最大 / top-k均值
组激活度:   Group.activation  = aggregate(成员束 activation)
库激活度:   Library.activation= aggregate(成员组 activation)

聚合函数可选:
  - sum:   总量(重视整体活跃)
  - max:   只要有一个活跃就高(重视"是否参与")
  - topk:  前k个平均(抗噪声,推荐)
```

### 2.3 重叠下的激活叠加
由于神经元属多束：
```
node.activity_total = base_activity + Σ_{束∈tracts(node)} 束对该神经元的贡献
```
- 参与越多活跃束 → 总激活越高（**复用增强**）
- 实现：按束迭代累加，稀疏跳过未点亮的束

### 2.4 激活度的衰减（时间维度）
```
activity(t+1) = decay·activity(t) + new_input
```
- `decay < 1`（如 0.9）：**不用就衰退**（用进废退）
- 保证激活度是"近期活跃度"而非"历史累加"

## 3. 分级加载调度（TierManager）

### 3.1 存储层级
```
L0 VRAM  12GB  ← activity > θ_high   (正在思考的)
L1 RAM   16GB  ← θ_low < activity ≤ θ_high (候选)
L2 NVMe       ← activity ≤ θ_low     (沉睡)
```

### 3.2 加载粒度选择（按组织单位）
```
if 某神经库 activity 高 → 整库加载(最大吞吐)
elif 某神经组 activity 高 → 整组加载
elif 某神经束 activity 高 → 整束加载
else 单个高活神经元 → 单独提升(最细粒度)
```
**原则**: 优先按**大单位**批量搬运（省 I/O），只在"大单位不活跃但个别神经元活跃"时才细粒度。

### 3.3 滞回窗口（防抖动）
```
提升阈值 θ_high = 0.6    (超过才进 VRAM)
降级阈值 θ_low  = 0.35   (低于才出 VRAM)
θ_low < θ_high → 中间地带不来回搬
```
**这是防"加载抖动"的关键**——否则活跃度在阈值附近波动会导致疯狂搬运。

### 3.4 预取（面向思考流）
```
思考流当前主题 → 预测"接下来可能激活的组织" → 提前从 NVMe 拉到 RAM
```
- 依据：激活扩散模式、历史共激活统计、当前语义主题
- **神经组织的语义性让预取可做**（张量页无此能力）

### 3.5 调度伪代码
```python
def tick_scheduler(nervous_system, dt):
    # 1. 更新激活度
    for n in nervous_system.neurons.values():
        n.activity *= decay
    for t in nervous_system.tracts.values():
        t.activation = aggregate([nervous_system.neurons[i].activity for i in t.neurons])
    for g in nervous_system.groups.values():
        g.activation = aggregate([nervous_system.tracts[i].activation for i in g.tracts])
    for lib in nervous_system.libraries.values():
        lib.activation = aggregate([nervous_system.groups[i].activation for i in lib.groups])

    # 2. 分级加载(滞回)
    for lib in nervous_system.libraries.values():
        if lib.activation > THETA_HIGH and lib.tier != "vram":
            promote(lib, to="vram")        # 可能先腾出空间
        elif lib.activation < THETA_LOW and lib.tier == "vram":
            demote(lib, to="ram")

    # 3. 预取
    predicted = predict_next_active(nervous_system, current_thought_topic)
    for lib in predicted:
        if lib.tier == "nvme":
            prefetch(lib, to="ram")
```

## 4. 思考流（永不停止的主循环）

### 4.1 主循环
```python
def thought_loop():
    while True:                                  # 永不停止
        # 1. 感知输入(如果有)
        inp = poll_inputs()                      # 非阻塞,可能为空
        if inp: enqueue_into_thought(inp)        # 按属性(紧迫/新奇/相关)排序

        # 2. 激活扩散
        seed = current_thought_topic             # 当前思考主题
        spread_activation(seed)                  # 沿神经束/组扩散

        # 3. 加载活跃组织
        tier_manager.ensure_loaded()             # 把高激活组织拉进 VRAM

        # 4. 前向计算(用活跃组织)
        state = compute(nervous_system.active_set())

        # 5. 在线可塑(激活即优化)
        update_plasticity(nervous_system.active_set(), state)

        # 6. 决定输出
        decision = decide_output(state, input_queue)
        if decision.should_output:
            emit(decision.content, decision.modality)

        # 7. 输出回灌(带护栏)
        if decision.emitted:
            feed_back(decision.content, guard=entailment_check)

        # 8. 自发行为(无输入也会发生)
        if input_queue.empty() and rand() < self_initiate_prob:
            self_generate_task()                 # 自发提问/查资料/练习

        # 9. 低活期→睡眠巩固
        if is_low_activity_window():
            sleep_consolidate()

        yield state
```

### 4.2 刺激来源（思考不止于外部输入）
| 来源 | 例子 |
|---|---|
| 外部输入 | 用户消息、传感器、屏幕 |
| 记忆回放 | 想起之前的事 |
| 联想 | A 想到 B |
| 自发提问 | "那个我没懂，查一下" |
| 未完成任务 | 之前挂起的目标 |
| 随机扰动 | 探索性思考（避免僵化） |

### 4.3 输出的自主决策
```python
def decide_output(state, inputs):
    # 不是"有输入就输出"，而是think后的判断
    if 有紧迫输入且已想清:      return Output(content, now=True)
    if 有输入但需深想:          return Output(pending=True)   # 稍后
    if 输入只需记录:            return Output(content=None)   # 只记不答
    if 自发地有话要说:          return Output(spontaneous=True)
    if 需要外部信息:            return Output(tool_call=True)
    return Output(content=None)
```

## 5. 在线可塑（激活即优化）

### 5.1 只有"被激活"的神经元可塑
```python
def update_plasticity(active_set, state):
    for n in active_set:
        if n.activity > PLASTIC_THRESHOLD:      # 只有活跃的才变
            n.plasticity += eta * local_update(n, state)
```
- **用进则变**：活跃的才改，安静的保持
- `local_update` 可用 Hebbian 或局部梯度（§6）

### 5.2 因果性保证
```
处理序列 t=1..T 时:
   对每个 t:  计算用当前参数 → 更新只写 plasticity(临时) → 不影响 1..t 已算
```
临时可塑量与"主体权重"分离，**前向只读主体+临时，写完只影响未来**。

### 5.3 Hebbian 更新（仿生首选）
```
Δplasticity = η·(pre ✗ post) - λ·plasticity
```
- `pre ✗ post`：前后共激活 → 增强
- `-λ·plasticity`：衰减 → 不用就忘
- η/λ 可学习

## 6. 睡眠合并（低活期巩固）

### 6.1 触发
- 全局激活度降到阈值以下（真正"低活期"）
- 或累积可塑量超过阈值
- 或显存宽裕时（避免和思考抢）

### 6.2 合并流程
```python
def sleep_consolidate():
    assert no_active_compute()                 # 必须无活动计算
    # 1. 惊讶优先重放(SuRe式)
    samples = select_surprising(experience_buffer)
    for s in samples: replay_and_accumulate(s)
    # 2. 正交投影(防遗忘)
    for n in plastic_neurons:
        n.plasticity = project_orthogonal(n.plasticity, n.importance)
    # 3. 合并入主体
    for n in plastic_neurons:
        n.base = merge(n.base, n.plasticity, mode="reversible")
        n.plasticity *= 0                      # 清零,重新开始
    # 4. 存检查点(可回滚)
    save_checkpoint()
```

### 6.3 4bit 主体的合并坑
- 若主体量化存放，**朴素合并会毁掉适配**（Scale-QLoRA 2609.04526）
- **对策**：冻结 code plane，只更新 per-block scale

## 7. 存储布局（12GB 怎么分）

```
┌──────────────── VRAM 12GB ────────────────┐
│ 活跃神经组织 (最高激活)         可变 6-9GB │
│ KV/激活缓存(当前思考)           1.5-2.5GB │
│ 临时可塑量(plasticity)          100-500MB │
│ 激活度索引/组织表                数十 MB   │
│ 工作区(合并时)                   分时 1-2GB│
└───────────────────────────────────────────┘
        ↕ PCIe
┌──────────────── RAM 16GB ─────────────────┐
│ 候选神经组织(次活跃) | 工作记忆 | 判分器   │
└───────────────────────────────────────────┘
        ↕ NVMe
┌──────────────── 磁盘 ─────────────────────┐
│ 全部神经库主体 | 长期记忆 | 回放素材 |检查点│
└───────────────────────────────────────────┘
```

| 参数 | 建议 | 说明 |
|---|---|---|

| 聚合函数 | top-k 均值 | 抗噪声 |
| 自发行为概率 | 低（如 0.01/step） | 别太频繁 |

## 10. 硬骨头与对策

| 硬骨头 | 底层原因 | 对策 |
|---|---|---|
| 激活度算不准 | 聚合方式影响调度 | top-k 均值 + 可学习权重 |
| 加载抖动 | 阈值附近震荡 | **滞回窗口** + 束级批量 |
| 重叠开销 | 神经元属多束难算 | 稀疏:只遍历点亮的束 |
| 搬运慢 | NVMe→VRAM 有延迟 | 预取 + 大单位批量 + PCIe 流水 |
| 自指不一致 | 思考中改参数 | 临时可塑量分离,只影响未来 |
| 遗忘 | 合并覆盖 | 正交投影 + 惊讶重放 |
| 显存爆 | 活跃组织太多 | 分级加载本身就是解;限并发 |
